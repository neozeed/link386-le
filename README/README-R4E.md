# LINK386 R4E — CMD32 multi-object source-only LE linker (experimental)

**Date:** 2026-10-17. **Status:** native Linux GCC/Clang and independent Microsoft-image oracle verified; Windows/os2host32 execution **not yet tested**.

This is a new source-only `LINK386` workalike milestone built in a **separate R4E tree**. The live-proven R4D-FIX1 hello baseline (and earlier R4B reference-assisted baseline) are **FROZEN AND UNMODIFIED**. R4E extends the exact known-good hello path to the supplied CMD32 objects, first the small console bridge test, then the full seven-object CMD32 shell.

All executable bytes were generated by R4E from application OMF `.OBJ` files plus original `LIBC.LIB`, `OS2386.LIB`, and `.DEF` import lists. The Microsoft EXEs are **only read by the post-build verification script**. The larger output sizes arise primarily from our simple ungrouped LE loader records and differing metadata packing; binary-identical output is **not** claimed.

## What was implemented in R4E

* Real multiple input objects with archive selection and the original Microsoft C/386 runtime.
* Limited `.DEF` parser for `IMPORTS name=DLL.ordinal`. Missing `VIOCALLS`, `KBDCALLS`, `SESMGR` import libraries are neither needed nor fabricated: DLL ordinal binding comes from `.DEF` and remains a runtime dependency.
* Mixed 32-bit and 16-bit code objects, preserving the genuine 98-byte C/386 16-bit bridge.
* 16-bit selector, 16:16 and 16:32 far-pointer OMF fixups, in addition to OFF32 and REL32 and LIDATA replication.
* OMF frame=GROUP(DGROUP) static, data-group-relative symbol addressing. The `strtol.asm` `_errno` pointer specifically exposed this case.
* `XI`, `XP` and other class/segment precedence within initialized data. The first full-CMD32 attempt had 20 byte differences from wrong `XI`/`XP` ordering.
* Correct 32-bit arithmetic even on LP64/Linux, avoiding an internal-target offset larger than 32 bits.
* Generated MZ/LE header, page map, per-object flags, import module table, import-ordinal fixups, internal fixups and physical initialized pages. BSS/stack remain virtual/zero-filled.
* DOSCALLS + VIOCALLS + KBDCALLS for the console test; plus SESMGR for CMD32.
* Explicit `--stack=61440` for the full CMD32 shell; `.DEF` STACKSIZE is not yet automatically parsed.

## Build & verify under Linux

```sh
make link386r4e
make verify-r4e
make verify-r4d-fix1  # prove frozen hello regression remains valid
```

Rebuild the console test (from project root):

```sh
mkdir -p build/r4e/console
./link386r4e -o build/r4e/console/cmdos2_os2_console_test-r4e.exe \
  -d fixtures/cmd32/shell/cmdos2_os2_console_test.def \
  fixtures/cmd32/shell/cmdos2_os2_console_test.obj \
  fixtures/cmd32/shell/cmdos2_os2.obj \
  fixtures/cmd32/shell/cmdos2_env.obj \
  fixtures/LIBC.LIB fixtures/OS2386.LIB
```

Rebuild the seven-object CMD32 shell (from project root):

```sh
mkdir -p build/r4e/full
./link386r4e -o build/r4e/full/cmd32os2-r4e.exe \
  -d fixtures/cmd32/shell/cmd32os2_os2.def --stack=61440 \
  fixtures/cmd32/shell/cmd32os2.obj \
  fixtures/cmd32/shell/cmdparse.obj \
  fixtures/cmd32/shell/cmdbatch.obj \
  fixtures/cmd32/shell/cmdfile.obj \
  fixtures/cmd32/shell/cmdos2_os2.obj \
  fixtures/cmd32/shell/cmdos2_session_os2.obj \
  fixtures/cmd32/shell/cmdos2_env.obj \
  fixtures/LIBC.LIB fixtures/OS2386.LIB
```

`rebuild-r4e.cmd` gives the corresponding MinGW/Windows commands.

## Windows/os2host32 verification — **not yet performed**

First use `--scan` on the **console** test, then attempt `--run` (it waits for one key). Its original source prints `M29H_OS2_CONSOLE_BACKEND_OK` on successful completion:

```bat
\OS2\os2host32.exe --scan cmdos2_os2_console_test-r4e.exe
\OS2\os2host32.exe --run cmdos2_os2_console_test-r4e.exe
```

Then scan and, if suitable, run the complete shell:

```bat
\OS2\os2host32.exe --scan cmd32os2-r4e.exe
\OS2\os2host32.exe --run cmd32os2-r4e.exe
```

If rejected by the loader, preserve the complete scan/run log. **Do not mark R4E live-proven on the strength of the static byte oracle alone.**

## Known limitations

R4E is not a general-purpose LINK386. It is an **experimental C/386 CMD32-profile** 3-object LE generator. It accepts the narrow tested set of OMF relocations/DEF ordinal syntax, not all LINK386 options/DEF directives/OMF record types. It does not create MAP output, does not pack fixup source lists like Microsoft, does not support arbitrary object counts or broad PM apps yet, and has not been runtime-validated for 16-bit bridge loading under the user's os2host32. Its synthesized page descriptors may differ from Microsoft's representation of long virtual BSS extents. The full shell requires the external `--stack=61440` option. Other programs may fail closed.

## Evidence

`make verify-r4e` invokes strict source-only builds **first**, then compares mapped initialized object bytes against the original Microsoft LE files while masking only import-operand positions. Both test binaries have **zero remaining unmasked differences** for all three objects. The generated LE records can be parsed with the independent R3S verifier (319 source sites for console; 1,231 for full CMD32).

See `HANDOFF-R4E.md` and `build/r4e/verify.log` for technical details and provenance.
